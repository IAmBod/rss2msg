# rss2msg v1.5 — Design

Status: approved (brainstorming)
Date: 2026-05-28
Builds on: `2026-05-28-rss2msg-design.md` (v1)

## Purpose

Two additions to v1:

1. **Multi-instance readiness.** Run more than one `rss2msg` process against
   the same config without double-polling each feed. Pluggable coordinator
   interface with two implementations in this milestone.
2. **SQS and SNS publishers.** Replace the v1 stubs with real AWS SDK v2
   implementations.

Everything else from v1 (state store, sinks, retry/DLQ, telemetry,
testcontainers tests) carries forward unchanged.

## Multi-instance coordination

### Goals and non-goals

- Goal: multiple `rss2msg` instances behind one config never both publish the
  same item from the same poll cycle.
- Goal: the coordination layer is swappable. Postgres-backed advisory locks
  ship in this milestone; a Redis or lease-table backend can follow without
  pipeline changes.
- Non-goal: cross-instance load balancing or sticky-feed assignment. Any
  instance may pick up any feed each cycle.
- Non-goal: solving the "one instance succeeds publish, another retries and
  publishes again" case at the publisher level. The v1 at-least-once contract
  still applies; coordination just prevents two instances from racing on the
  *same poll cycle*.

### `Coordinator` interface

New package `internal/coord`:

```go
package coord

import "context"

type ReleaseFunc func(ctx context.Context) error

type Coordinator interface {
    // TryAcquire returns (release, true, nil) if this instance just won the
    // lease for feedURL. The caller must call release() before its next poll
    // attempt for the same feed.
    //
    // Returns (nil, false, nil) if another instance currently holds the lease
    // (the caller should skip this poll cycle).
    //
    // Returns (nil, false, err) on infrastructure failure. The caller treats
    // this the same as not-acquired: skip this poll, increment the
    // coord_error metric, log at warn.
    TryAcquire(ctx context.Context, feedURL string) (ReleaseFunc, bool, error)

    Close() error
}
```

### Implementations shipped in v1.5

**`internal/coord/noop`.** Always returns `(noopRelease, true, nil)`.
`noopRelease` is a function that returns nil. Used as the default when no
`coordination.driver` is set, and for local dev / single-instance deployments.

**`internal/coord/postgres`.** Uses `pg_try_advisory_lock(int8)` keyed by the
first 8 bytes of `sha256(feed_url)` interpreted as `int64`. Implementation
notes:

- Postgres advisory locks are tied to a *session*. The lock and unlock must
  run on the same physical connection. So `TryAcquire` calls
  `pool.Acquire(ctx)` to pin a conn, runs `pg_try_advisory_lock`, and stores
  the pinned `*pgxpool.Conn` in a closure captured by the returned
  `ReleaseFunc`.
- `ReleaseFunc` runs `pg_advisory_unlock` on the pinned conn, then calls
  `conn.Release()` to return it to the pool.
- If `pg_try_advisory_lock` returns false, the function releases the conn
  immediately and returns `(nil, false, nil)`.
- If the instance crashes, the conn closes, Postgres drops the session, and
  the lock is released automatically — no TTL or janitor required.
- The coordinator's pgx pool is sized via `pgxpool.Config.MaxConns =
  max(defaultMax, len(feeds))` so a fan-out poll never starves on conn
  acquisition. The feed count is plumbed from `cfg.Feeds` at `wireAll` time
  via a `MinConns` argument on `coordpg.New`.

### Config

```yaml
coordination:
  driver: postgres        # postgres | noop ; default noop
  postgres:
    dsn: ${POSTGRES_DSN}  # optional; falls back to state.postgres.dsn
```

When the section is omitted entirely the loader treats it as
`driver: noop` so single-instance dev keeps working without config changes.

### Validation rules

- `coordination.driver` must be one of `"noop"`, `"postgres"`, or `""`
  (=noop).
- When `coordination.driver=postgres`, `coordination.postgres.dsn` must
  resolve to a non-empty string after env-var substitution; if it's empty,
  `state.postgres.dsn` is reused. If both are empty, startup fails.

### Pipeline integration

`pipeline.RunOnce` gains a single guard before the existing `feed.poll` span
body:

```go
release, acquired, err := p.coord.TryAcquire(ctx, feedURL)
if err != nil {
    p.instr.PollSkipped.Add(ctx, 1,
        metric.WithAttributes(attribute.String("reason", "coord_error")))
    log.Warn().Err(err).Msg("coordinator error; skipping poll")
    return nil, nil
}
if !acquired {
    p.instr.PollSkipped.Add(ctx, 1,
        metric.WithAttributes(attribute.String("reason", "not_owner")))
    log.Debug().Msg("another instance owns this poll; skipping")
    return nil, nil
}
defer func() { _ = release(ctx) }()

// ... existing fetch/parse/detect/publish path unchanged
```

The skip path returns `nil, nil` — same shape as a 304 Not Modified, so the
scheduler treats it identically.

### New metric

- `feed.poll.skipped` — `Int64Counter`. Attributes: `feed_url`, `reason`
  (`not_owner` | `coord_error`). Added to `telemetry.Instruments`.

### Wiring

`cmd/rss2msg/wire.go` gains `openCoordinator(ctx, cfg.Coordination,
cfg.State)`:

- `noop` → `coordnoop.New()`.
- `postgres` → `coordpg.New(ctx, dsn)` where `dsn` is the resolved fallback
  chain above.

Exactly one `Coordinator` is constructed and shared across all
`*pipeline` instances. The shared instance owns the pgx pool.

## SQS publisher

### Package layout

Replace `internal/sink/sqs/sqs.go` (the v1 stub) with a real implementation.
Keep the package path so the `buildPublisher` switch in
`cmd/rss2msg/wire.go` only changes the dispatched constructor call.

### Dependencies (new)

- `github.com/aws/aws-sdk-go-v2/config`
- `github.com/aws/aws-sdk-go-v2/service/sqs`

### Options

```go
type Options struct {
    Name        string // required, sink name
    QueueURL    string // required
    Region      string // optional; SDK default chain used when empty
    EndpointURL string // optional; LocalStack/testing
}
```

### Construction

`New(ctx, opts)` uses `config.LoadDefaultConfig(ctx, optionalOverrides...)`.
Overrides:

- `Region` when non-empty.
- When `EndpointURL` is non-empty, the SQS client is built with
  `sqs.NewFromConfig(cfg, func(o *sqs.Options) { o.BaseEndpoint = &endpoint })`
  using the per-service `BaseEndpoint` field (AWS SDK v2's current
  endpoint-override mechanism; the older
  `aws.EndpointResolverWithOptionsFunc` is deprecated and should not be used).

Returned `Publisher` keeps the `*sqs.Client`.

### Wire format

- `MessageBody` = JSON-marshalled `model.Change` (same envelope as Kafka and
  Postgres).
- `MessageAttributes` (all `DataType: "String"`):
  - `feed_url`
  - `kind`
  - `schema_version`
  - `traceparent` — only when an active OTEL span context exists (read via
    `otel.GetTextMapPropagator().Inject` into a `propagation.MapCarrier`,
    same approach as Kafka).
  - `dlq_from_sink`, `dlq_error`, `dlq_attempts` — only when `change.DLQFromSink != ""`.
- One `SendMessage` call per `Publish` invocation.

### FIFO handling

FIFO queues are out of scope for v1.5. Construction fails fast if `QueueURL`
ends with `.fifo` — the user gets a clear error pointing at the omission
rather than runtime errors about missing `MessageGroupId`. Adding FIFO
support later is a separate, additive change.

## SNS publisher

Symmetric to SQS.

### Dependencies (new)

- `github.com/aws/aws-sdk-go-v2/service/sns`

### Options

```go
type Options struct {
    Name        string // required
    TopicARN    string // required
    Region      string // optional
    EndpointURL string // optional
}
```

### Construction

Same default-chain pattern as SQS. The SNS client uses
`sns.NewFromConfig(cfg, func(o *sns.Options) { o.BaseEndpoint = &endpoint })`
when `EndpointURL` is set.

### Wire format

- `Message` = JSON-marshalled `model.Change`.
- `MessageAttributes` (all `DataType: String`): same five-to-eight keys as
  SQS.
- `Publish` calls `client.Publish`.
- Topic ARN ending in `.fifo` is rejected at construction time.

## Configuration shape changes

```yaml
coordination:
  driver: postgres
  postgres:
    dsn: ${POSTGRES_DSN}

sinks:
  - name: sqs-main
    driver: sqs
    sqs:
      queue_url: https://sqs.us-east-1.amazonaws.com/123/feed-changes
      region: us-east-1
      endpoint_url: ""
    dead_letter: dlq-pg
  - name: sns-main
    driver: sns
    sns:
      topic_arn: arn:aws:sns:us-east-1:123:feed-changes
      region: us-east-1
```

Typed structs added in `internal/config/config.go`:

```go
type CoordinationConfig struct {
    Driver   string              `mapstructure:"driver"`
    Postgres CoordinationPGConfig `mapstructure:"postgres"`
}

type CoordinationPGConfig struct {
    DSN string `mapstructure:"dsn"`
}

type SinkConfig struct {
    // ... existing fields
    SQS SQSSinkConfig `mapstructure:"sqs"`
    SNS SNSSinkConfig `mapstructure:"sns"`
}

type SQSSinkConfig struct {
    QueueURL    string `mapstructure:"queue_url"`
    Region      string `mapstructure:"region"`
    EndpointURL string `mapstructure:"endpoint_url"`
}

type SNSSinkConfig struct {
    TopicARN    string `mapstructure:"topic_arn"`
    Region      string `mapstructure:"region"`
    EndpointURL string `mapstructure:"endpoint_url"`
}
```

`Config` gains `Coordination CoordinationConfig`.

### Validation rules (additions)

- `coordination.driver` ∈ {`""`, `"noop"`, `"postgres"`}; unknown rejected
  with `coordination.driver %q is not supported`.
- `coordination.driver=postgres` requires a resolvable DSN (own or fallback
  to state).
- `sinks[i].driver=sqs` requires `sqs.queue_url` non-empty; rejected if it
  ends with `.fifo` (with message pointing at "FIFO not supported in this
  version").
- `sinks[i].driver=sns` requires `sns.topic_arn` non-empty; rejected if it
  ends with `.fifo`.

All other v1 validation rules unchanged.

## Testing

### Unit tests

- `internal/coord/noop` — trivial assertion that `TryAcquire` always returns
  acquired+true and release is a no-op.
- `internal/config/validate` gains 4 new cases:
  - Accepts the new minimal good config (postgres coordination + SQS sink +
    SNS sink, leveraging state DSN fallback).
  - Rejects unknown coordination driver.
  - Rejects FIFO SQS URL.
  - Rejects FIFO SNS ARN.

### Integration tests (`//go:build integration`)

- `internal/coord/postgres` — single Postgres testcontainer.
  - Two `Coordinator` instances against the same DB race for the same
    feed URL; assert exactly one gets `acquired=true`.
  - After the winner releases, the previously-blocked instance can acquire.
  - Closing a `Coordinator` releases held locks (drains pool).
- `internal/sink/sqs` and `internal/sink/sns` — single LocalStack
  testcontainer shared via a small helper in `test/awslocal/`. The helper
  exposes per-test queue/topic creation and the `endpoint_url` to pass to the
  sink. Each test:
  - Constructs the sink, publishes a `Change`, asserts the message arrives
    on the other side.
  - Asserts the standard `MessageAttributes` round-trip.
  - One test per package sets an active OTEL span and asserts `traceparent`
    appears in attributes.
  - One test per package publishes a DLQ-decorated `Change` and asserts the
    three DLQ attributes appear.

### E2E

The v1 e2e test (`test/e2e/e2e_test.go`) is not expanded — adding SQS/SNS
there would force LocalStack into the critical-path e2e and slow it
significantly. SQS/SNS coverage stays in their package-level integration
tests.

## Wiring changes summary

`cmd/rss2msg/wire.go`:

- Add `openCoordinator(ctx, cfg.Coordination, cfg.State)`.
- Add `coord` field to `pipeline`; pass the shared coordinator into every
  pipeline.
- Replace `buildPublisher`'s stub cases for `sqs`/`sns` with real
  constructors using the new `Options` types.
- `wired.Close` now also closes the coordinator (after registry, before state
  store — coordinator is the cheapest to release).

`cmd/rss2msg/pipeline.go`:

- Add `coord coord.Coordinator` field.
- Add the acquire/release guard described in §"Pipeline integration".

`internal/telemetry/telemetry.go`:

- Add `PollSkipped metric.Int64Counter` to `Instruments`; created in
  `NewInstruments` with name `feed.poll.skipped`.

## Documentation

`README.md` additions in the existing "Operational notes" section:

- **Running multiple instances.** Set `coordination.driver=postgres` and
  ensure every instance shares the same Postgres DB. No leader election; any
  instance may poll any feed each cycle. Crashed instances release their
  locks automatically.
- **AWS credentials.** Standard SDK chain (`AWS_ACCESS_KEY_ID`,
  `~/.aws/credentials`, instance metadata, etc.). The config carries only
  region, queue/topic, and an optional `endpoint_url` for LocalStack.
- **LocalStack for development.** One-line `docker run` plus the relevant
  `endpoint_url: http://localhost:4566` in `config.yaml`.

`config.example.yaml` gains the `coordination:` block and example SQS/SNS
sinks, commented appropriately.

## Out of scope for v1.5

- FIFO SQS / SNS.
- Cross-region SQS/SNS in a single sink (one sink = one region).
- Coordinator backends beyond `noop` and `postgres`.
- Per-instance feed sharding (sticky assignment).
- OTLP exporter affinity / read-side load balancing across instances.
- Replacing the v1 "commit on success" model with an outbox pattern (still
  the right trade-off for v1.5).
